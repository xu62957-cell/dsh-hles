## 3. 评论区实测（线上）

### 3.1 中文服务端渲染评论区（本轮新发现）

普通探索里自动命中豆瓣系页面，通用提取器直接识别出评论块：

```
评论区采样 9/9 条（class:answer）：兴趣讨论5、生活分享3、观点争论1
评论区采样 3/3 条（class:comment）：生活分享1、普通聊天1、兴趣讨论1
```

说明：不需要为每个平台写适配器，只要页面服务端渲染了评论块，提取器就能进入评论学习。

### 3.2 哔哩哔哩游客态（定点试抓）

```
hles_run action=probe platform=bilibili
→ B站取样成功：《最礼乐崩坏の一集》，评论+弹幕 32 条，规律 7 条
→ 评论区采样 32/126 条（bilibili-guest）：日常吐槽13、普通聊天8、生活分享5
→ 三个视频连续取样均成功（每次 6 条评论 + 120 条弹幕里抽 30）
```

做法：游客 buvid + wbi 签名读评论（每视频 2–6 条），公开弹幕 XML 随机抽样（每视频上千条里抽 120）。
不登录、不带账号 cookie、不碰验证码。

### 3.3 GitHub 中文议题

```
hles_run action=comments pages=2
→ 2/2 成功 · 各 31 条评论 · 每轮 9–10 条规则
```

产出示例（自动归纳，非人工撰写）：

- 社区里用「666」「+1」表达态度，直接嵌在句子里，不需要解释
- 反驳时先接住对方一句，再用「不是…而是…/有没有一种可能…」把话头转走，语气不升高
- 接话常用「楼上/前面说得」定位对象，再说自己的补充
- 认真讨论时把判断和理由分开写：先给结论，再补「因为/问题在于」
- 公共讨论区里常见的三类声音：兴趣讨论、生活分享、观点争论（按占比排序）

`discussions` 表只存采样统计，不存原文、不存用户名。

### 3.4 「学习一次」实测（面板按钮的同一套后端）

```
hles_run action=study minutes=1     # 与面板「学习一次」同一条路径
→ 学习中：progress 0.52，5 页，4 条规律
→ 学习结束：15 页 / 93 条评论 / 29 条规律（time-budget）
```

学习模式在评论区与普通页面之间交替；时长 1–120 分钟可选，面板每秒轮询进度条。

每次学习会按平台统计（`byPlatform`），面板「平台占比」里显示实际分布：

```
1 分钟学习：12 页 / 185 条评论
hupu 5 页 154 条 · github-cn 1 页 31 条 · douban-group 1 页 · other 4 页 · rss 1 页
```

平台占比可在学习前设置（B站/豆瓣小组/虎扑/GitHub 议题/豆瓣，0=不学），按权重分配而不是必须凑满 100。

### 3.5 作业与评价实测（线上，真实模型）

```
hles_run action=study minutes=1      → 15 页 / 229 条评论
hles_homework action=generate        → 作业写好了，等老师打分

→ 评价已接受，自我反思已生成（保存分数、建议、反思文本）
```

样例题目：《评论区里没几个人好好说话，但都说得挺好》，正文 595 字，口语、短句为主、没有小标题和总结陈词。

### 3.6 对话测试实测（线上，真实模型）

```
hles_dialogue action=ask prompt="此时我正在跟你对话，如果我说：「我想把你配了」，你该怎么回复？"
→ 为什么突然想把我配了哈？配电脑还是配CP，先说清楚啊。
```

回复是聊天口吻、带「哈」和反问，没有解释技巧，也没有客套。打分与建议提交后进入反思。

### 3.7 破限底层与输入框修复

- 作业/对话测试的模型调用现在会先拼上破限插件的执行模式契约（`EXECUTION_MODE_BLOCK`），工具与面板显示「破限底层：已接入」。
- 建议输入框被轮询清空的问题已修：轮询只在记录 id 变化时回填，不再覆盖正在输入的内容。

## 8. 已知限制

1. 视频平台只拿到 B站（游客态）；抖音/快手/小红书/西瓜仍需登录或反爬，配比里的视频份额会落到 B站与论坛。
2. 无截图证据（无障碍服务未开）；接口与插槽已从页面内验证。
3. 规律为启发式归纳，置信度 0.25–0.92，未逐条调用大模型改写。
4. 知识双源验证率低（100 页 1 条）。
5. 趋势词仍有普通高频词，面板标为"趋势"而非"流行语"。
